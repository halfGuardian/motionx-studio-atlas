## Practical human review and publication control

The new worksheet contains **91 content-bound items**: 59 companies, 27 identity keys, the separate closure alert and four facilities. Each includes evidence, recommended handling and blank decision/note fields. The original **29-entry NZ** worksheet and historical **37-row Annecy** human precision review remain byte-for-byte unchanged.

The dashboard allows working choices: accept provisional reference, existing/alias, needs evidence, identity conflict, out of scope, historical/inactive investigation or rights review. Downloaded choices are **unauthenticated local working notes** with no reviewer asserted, `human_approved:false` and `publication_authorised:false`. No importer consumes this file; no POST, backend or automatic database write is added. Clicking accept, opening a link, running tests and agent-written recommendations are not human approval.

Generated `human_approved:false` metadata asserts no completed per-item evidence approval; it does not query or attest the live GitHub review state. A human can authorise publishing a clearly labelled research lead without independently verifying a facility.

This PR uses **manual review of the exact PR commit and an authorised merge**, consistent with the v1.2–v1.4 Class C model. It does not invent or reuse a content-bound approval bundle. Existing separate bundle safeguards remain unchanged. GitHub required-review/branch-protection enforcement has not been independently confirmed for this update: draft status and passing Actions alone do not enforce review. The maintainer must review evidence, the 27 minimal-rights scopes, the two staged decisions, current-operation uncertainties and any later facility/correction proposals before authorising publication.
